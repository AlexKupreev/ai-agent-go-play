> **Role: dated audit input.** The open findings are consolidated and ordered in
> [`roadmap.md`](roadmap.md). Keep this document as the detailed evidence snapshot rather than a
> second competing backlog.

Successor to [`review-2026-07.md`](review-2026-07.md) (whose §1–§3 are done except the
explicitly-deferred tail). Findings from a fresh pass: every doc read end-to-end, plus the
cmd layer, agent core, tool surface, capability broker, sandbox, API layer, space/session
stores, and the Fly deployment. `go build ./...`, `go vet ./...`, and `go test ./...` all pass.

The centre of gravity has moved: since the last review the project shipped **spaces**, the

inconsistency below traces to one of those four — the code moved, the older reference docs
did not follow.

Three sections:

1. **Fixes** — errors and doc/code inconsistencies, ranked by damage.
2. **Flexibility** — making behaviour changeable at runtime, especially *by the user*.
3. **Informativeness** — making the agent and the CLI able to say what is actually true.

Boxes are unchecked work, matching [`plan.md`](plan.md) conventions.

## 0. Overview — what the project is today

**Implementation** (~15k lines of non-test Go, ~9k of tests, all packages covered):

| Layer | Packages | State |
| --- | --- | --- |
| Kernel | `internal/agent` (ReAct loop, planner, critic, summarize, agent types, observers) | mature; `agent.go` is 1011 lines and is the one file doing too much |
| Tools | `internal/tools` — 23 built-ins + `ToolSpec` registry + `author_tool` | mature; the built-in surface has roughly tripled since it was last described in `tools.md` |
| Boundary | `internal/capability` (broker, tiers, secrets), `internal/sandbox` (gopher-lua) | mature and well-tested; the only clean subsystem boundary in the tree |
| State | `internal/memory`, `internal/space`, `internal/session`, `internal/artifact`, `internal/audit`, `internal/usage` | all JSON-file stores behind interfaces; SQLite still the stated end-state |
| Transport | `internal/api` (HTTP+SSE engine, runs, sessions, approvals, uploads) | mature |
| Frontends | `cmd` (13 cobra commands), `internal/frontend/telegram` | mature |

**Documentation** — ~8.4k lines across three tiers, and the tiering is genuinely good:

- **Reference** (`README.md`, `docs/*.md`) — embedded into the binary via
  `//go:embed README.md docs/*.md self-extending-agent-design.md`, so they *are* the agent's
  self-knowledge. **A stale reference doc is not a documentation bug, it is a runtime bug.**
- **Decision records** (`docs/adr/`) and **planning** (`docs/planning/`, `docs/deferred/`) —
  deliberately not embedded, so a roadmap can't be mistaken for a capability. Correct call.

The docs are unusually strong on *rationale* — the benefit/drawback framing in `tools.md`,
`memory.md`, and `security.md` is the best thing in the repo and should be preserved. The
weakness is **currency**: the "how it works now" statements have drifted, and because they are
embedded, the drift is load-bearing.

## 1. Fixes — errors and inconsistencies

### 1.1 The two-scope model is now self-contradictory (HIGH — embedded, and it is the core model)

The spaces ADR's governing decision (2026-07-08) moved memory to `<workspace>/.agent/memory.json`.
The code agrees (`cmd/config.go` `memoryPath`/`spacesDir`, `cmd/config_test.go:340`). Two
embedded reference docs still assert the opposite, **in the section that defines the project's
central abstraction**:

- `docs/design.md` §1: *"memory/tools/audit stay config-dir-scoped, so per-workspace separation
  means a second config-dir, not a second workspace."* — false for memory since 2026-07-08.
- `docs/environment.md` §Two scopes: the table says config-dir *Holds* "memory, tool catalog,
  audit, global prompt files", and the prose says **"Identity never flows down into a target.
  Memory, the tool catalog, and the audit log stay config-dir-scoped — a workspace does *not*
  get its own."** Then, 150 lines later in the same file, the files-on-disk table correctly
  lists `<workspace>/.agent/memory.json` and `<workspace>/.agent/spaces/<id>/`.
- `docs/usage.md` §Running multiple independent agents: *"Each agent's state — config, tool
  catalog, **memory**, and audit log — lives under one config directory"* — contradicts
  `usage.md`'s own §Long-term memory twelve sections earlier.
- `docs/tools.md` §Persistence: *"the same identity-vs-target split **memory** and the audit log
  follow"* — memory no longer follows it.

Consequence: ask the deployed agent "where is your memory?" and `read_self_docs` can hand it
either answer depending on which doc it lands on. It also mis-advises the highest-stakes
operational decision in the project — *"point `--workspace` at a persistent directory"*.

- [x] Rewrite `environment.md` §Two scopes to the real model. **Done 2026-08-20** — the section
      now leads with a state→scope table, names memory as the one deliberate exception, and calls
      out the two consequences (shared memory across config-dirs; workspace fixed at `serve`
      launch). Original wording: config-dir = **config, tool
      catalog, audit log, global prompt files**; workspace = **shell cwd, workspace prompt
      files, and the agent's memory + spaces**. Say plainly that memory is the one piece of
      *identity-shaped* state that lives in the *target* scope, and why (spaces ADR §Governing
      decision), rather than leaving the old principle standing next to the new fact.
- [x] Fix `design.md` §1's parenthetical and `tools.md` §Persistence's aside. **Done
      2026-08-20** (`memory.md` §Persistence too, which had the same aside).
- [x] Fix `usage.md` §Running multiple independent agents. **Done 2026-08-20** — the section is
      now a store→scope table plus a callout, and the worked example passes `--workspace` as well
      as `--config-dir`; `README.md` §Ways to run had the same error and is fixed. Was: two
      config-dirs no longer separate
      memory — **two config-dirs in the same workspace share memory and spaces**
      (`adr/spaces.md` §Governing decision, operational note 2). That is a genuine footgun and
      is currently documented backwards.

### 1.3 `read_self_docs` returns whole documents with no size cap (HIGH — context and cost)

`internal/tools/webfetch.go` caps a fetched page at `maxFetchChars = 10_000` with the comment
*"so one page cannot flood the model's context"*. `internal/tools/selfdocs.go` `Get` returns
`doc.body` unbounded. The embedded set contains:

```
docs/usage.md                    54,228 chars   (~14k tokens)
self-extending-agent-design.md   45,390 chars   (~12k tokens)
docs/design.md                   18,060 chars
docs/tools.md                    16,418 chars
```

So the agent's single largest context sink is the one tool with no cap — 5.4× the limit imposed
on untrusted web content. On the then-default `gpt-4o-mini` (128k) a single `read_self_docs
topic=usage` spends ~11% of the window; the prompt actively encourages the call ("consult
read_self_docs and answer from it rather than guessing"). On a 2 GB box paying per token this is
the most expensive routine operation in the system.

- [x] Document the cost: **done 2026-08-20** — `usage.md` §Self-documentation now states that
      `read_self_docs` returns whole documents with no cap, gives the sizes, and contrasts it with
      `web_fetch`'s 10,000-char limit.
- [x] **Done 2026-08-21**, taking the second option: every body the tool returns now goes
      through `truncateForContext` (the same 10,000-char cap and "[truncated — N chars total]"
      marker as `web_fetch`), and `usage.md` §Self-documentation is rewritten to match.
- [x] **Section retrieval landed 2026-08-21** (with §3.1). `selfdocs.splitSections` cuts each
      doc at every `^## ` outside a code fence; `topic=usage` returns the outline (1.8 KB) when
      the doc is over the cap, `topic=usage section=spaces` returns one section, and `query=`
      ranks sections. A whole-`usage` call went from 56,715 chars to 1,775.

### 1.4 `recent_activity` sees only the current run outside `serve` (MEDIUM) *(fixed 2026-08-21)*

`ExecutorConfig.AuditReader` is set to the **per-run** recorder in both `cmd/run.go:129` and

`<runs-dir>/<run-id>/audit.jsonl`). Only `cmd/serve.go` passes the process-wide reader.

audit log … 'what have I done recently?'"*.

- [x] Pass the central reader (`openCentralLedger`'s recorder already opens
      `<config-dir>/audit.jsonl` in both commands) as `AuditReader`, keeping the per-run
      recorder as the *writer*. This is a one-line change in each command and makes the tool
      mean the same thing everywhere.
- [x] Note in the tool description that non-`serve` runs record capability events only to the
      run transcript, so the central log holds `run_usage` for CLI runs (see §1.5).

**Done 2026-08-21** — run and local chat now use the process-wide reader, matching serve; eval
deliberately remains variant-local for reproducibility. The limitation paragraph in `usage.md` was
replaced with the shipped behavior and the write-side distinction.

### 1.5 `agent audit` has no local mode, but `agent usage` reads the same file locally (MEDIUM) *(fixed 2026-08-21)*

`usage.md` §Audit log then shows examples that imply local operation:

- [x] Fix the examples to carry `--addr` and say the command requires a running engine.

- [x] Give `audit` a local reader when `--addr` is not explicitly set (mirroring `usage`). This is

### 1.6 `scrape` failures are audited as `capability_denied` (MEDIUM — corrupts the security record) *(fixed 2026-08-21)*

Before the fix, `internal/tools/scrape.go` `record(host, renderJS, ok)` emitted
`EventCapabilityDenied` whenever `ok` was false — including a transport error, a read error, and
**any non-200**, i.e. a 404, a 500, or an out-of-credits 429. `security.md` §3 defines
`capability_denied` as a policy refusal by the broker. Mixing "the site 404'd" into the denial
stream made the one signal an operator would grep for — *"what did my agent try that policy
stopped?"* — mostly noise from a paid third-party API.

- [x] Record failures separately and keep `capability_denied` meaning *policy said no*.
      **Done 2026-08-21** — `capability_failed` is the third capability outcome. Broker and scrape
      failures carry a stable `error_class` plus HTTP `status` where available; they do not record
      raw errors or full URLs.
- [x] Preserve paid-call attribution on failure. **Done 2026-08-21** — failed scrapes keep their
      run id, target host, `[secret:scrapingant]`, and `[browser]` cost marker, so the spend ledger
      does not lose unsuccessful calls.

### 1.7 A session's `space` is accepted without validation; `tier` is not (MEDIUM) *(code fix open)*

`internal/api/sessions.go` validates `tier` at the transport boundary (`validateTierOpt` → 400)
precisely so *"a bad value can't be stored and silently break every future turn"*. `space` is
passed straight into `Engine.UpdateSession` with no check, because the engine core has no space

Result, already observed and written down in the working notes: `/space typo` in Telegram
succeeds, and **every subsequent message fails** with `no space "typo"` until the user works out
they must send `/space -`. The exact failure mode the tier validation exists to prevent.

- [ ] Add an injectable `SpaceValidator func(id string) error` on the engine (same seam shape as
      `SetSessionCloseHook` / `RunStore`), wired by `cmd/serve.go` to `space.Store.Resolve`.
      Unknown space ⇒ 400 at `POST`/`PATCH`, never a poisoned sticky.
- [ ] Make the failure self-correcting either way: the turn error should list the available
      spaces (`space.Store.List()`), not just report the miss. See §3.4.

## 2. Flexibility — changing behaviour without a rebuild, and by user guidance

Already good, keep as-is: hot-reloadable prompt/agent-type files, `agents/*.md` types with
per-type `model:`, `agent eval` variants, `limits` config, engine aliases, per-session sticky
model/tier/space, `openai_base_url`, secrets-by-name.

The gaps below are ordered by leverage. §2.1 and §2.2 are the two that matter.

### 2.1 The user has no guidance channel that doesn't require filesystem access (HIGHEST)

> **Terminology update (2026-08-21):** the earlier “notes” proposal below was unified into scoped
> guidance. Space guidance replaced `Space.Notes`; `/notes` is not part of the active roadmap.

Every way to shape the agent's standing behaviour is a **file on the box**: `SYSTEM.md`,
`AGENTS.md`, `PLANNER.md`, `CRITIC.md`, `agents/*.md`, and `space.json`'s notes. On the
canonical deployment — Fly, Telegram-only, no terminal — the user must `fly ssh console` and
hand-edit JSON to give the agent a standing instruction. `usage.md` says of space notes: *"You
can also edit `space.json` by hand"*, which is the whole user-facing story.

Space notes are the right primitive and are already agent-writable
(`update_space_notes`), always-loaded, and per-context. They are just not *user*-writable from
where the user actually is.

- [ ] **`/notes` in chat and Telegram** — `/notes` shows the active space's notes, `/notes <text>`
      replaces them, `/notes + <text>` appends. Backed by `PATCH /sessions/{id}` or a small
      `PUT /spaces/{id}/notes`. This is the single highest-value change in this document: it
      turns spaces from "agent-maintained scratch" into "the user's standing-instructions
      surface", which is what the always-loaded 4000-char blob is actually for.
- [ ] **A global notes scope** — the same mechanism with no space active, appended to every run
      in that workspace (`<workspace>/.agent/notes.md`). Today `AGENTS.md` fills this role but
      only from disk and only with a `/reload`.
- [ ] **`agent space` CLI** (`list`, `show`, `notes`, `notes set`, `rm`) — spaces are the only
      major store with no CLI at all, so they can't be inspected or repaired without opening
      JSON. Compare `agent tool list` / `agent session list`.
- [ ] **`agent prompts edit`** or at least surface, over the API, *which* prompt files are
      currently loaded (see §3.3) so a remote user can tell whether their edit took.

### 2.2 `SYSTEM.md` is all-or-nothing (HIGH — and it silently drops safety-relevant guidance) *(kernel blocks fixed 2026-08-21; `{{base}}` open)*

`baseSystemPrompt(override, docsNote, policyNote, rosterNote, scratchNote)` correctly
force-attaches the factual notes ("an operator can restyle the prompt but not silently erase
what the agent is and can do"). But the **built-in `executorPrompt` body** is replaced wholesale
by a `SYSTEM.md`, and that body carries things that are not style:

- the ~2 GB runtime constraints (*don't run Python/Node/Ruby/R via shell*),
- the `run_code`-has-no-I/O contract,
- the prefer-text-over-binary-formats rule,
- the worked `author_tool` analytics example the authoring loop depends on,
- **the untrusted-content / prompt-injection rule** (`security.md` §5 lists this system-prompt
  rule as half of the injection defence — a `SYSTEM.md` deletes it).

So the moment a user customizes the persona, the agent loses the injection rule and starts
reaching for Python on a box that will OOM-kill it. That is a surprising outcome for what reads
like a cosmetic knob.

- [x] Split `executorPrompt` into named blocks — `role`, `runtime_constraints`, `tool_doctrine`,
      `memory`, `security` — and force-attach `security` (and probably `runtime_constraints`)
      the way `policyNote` already is. `baseSystemPrompt` is already the composition point.
      **Done 2026-08-21** — four blocks (`executorRoleBlock` / `executorRuntimeBlock` /
      `executorDoctrineBlock` / `executorSecurityBlock`); `kernelPromptBlocks` re-attaches the
      runtime + security blocks over a `SYSTEM.md` and over a replace-mode `agents/*.md` type
      (which had the same hole), skipping a block the operator restated. Roadmap R0.
- [ ] *(carried to roadmap R2)* Support a **`{{base}}` placeholder** in `SYSTEM.md`: present ⇒ the built-in base is
      substituted in, so an operator can *wrap* ("You are Ada. {{base}} Always answer in
      Polish.") instead of choosing between persona and correctness. Absent ⇒ today's replace
      semantics, unchanged.
- [x] Document the distinction in `environment.md`: **done 2026-08-20** — a new
      "What a `SYSTEM.md` override does and does not remove" subsection with a survives/does-not
      table, naming the runtime constraints, the `author_tool` example, and the untrusted-content
      rule as the things an override silently drops, and pointing at `agent prompts show
      --no-context-files` to copy the base from. This makes the hazard visible; it does not
      remove it. The two boxes above are the fix.

### 2.3 `serve` freezes the workspace at startup — and the workspace now holds the data (HIGH)

`resolveWorkspace()` runs once in `cmd/serve.go`. Before the spaces move that only fixed the
shell cwd; now it also fixes **memory and every space** for the life of the process. A Telegram
user cannot change data root at all, and `subagents.md`/`workspace.md` still list "the `serve`
per-run `workspace` field" as a designed-for extension.

Spaces cover the *"switch context"* use case, which is probably why this hasn't bitten. But it
means the workspace is now the one scope with no runtime dial, while being the scope that owns
the durable data.

- [ ] Add `workspace` to `RunOptions` and to the session sticky set, tier-gated exactly like the
      prompt tier and rooted under a configured containment prefix (the `deferred/projects.md`
      containment argument applies unchanged).
- [x] Say so explicitly in `environment.md`: **done 2026-08-20** (§Two scopes consequence 2, and
      `usage.md` §Long-term memory).

### 2.4 The deliberate dials are serve-side only (MEDIUM)

`--no-plan` / `--no-critique` / `--max-revisions` are process-wide flags. Model, tier, and space
are all per-session sticky; deliberation is not, even though it is the dial with the largest
cost and latency effect (planner + executor + critic + re-plan = up to 4 model calls per
message). A user who wants one quick factual answer must restart the engine.

- [ ] Add `plan` / `critique` / `max_revisions` to `RunOptions` + the session sticky set, with
      the same merge order (turn > session > serve default) and the same clamp discipline the
      tier uses (a serve-side `--no-plan` should stay a ceiling, not be overridable upward, if
      the operator meant it as a cost control).
- [ ] `/deliberate on|off` in chat and Telegram, alongside `/model` and `/tier`.
- [ ] This also unblocks `review-2026-07.md` §2.5's deferred per-variant `plan`/`critique` in
      `agent eval` — once the dials are `RunOptions` fields, eval can sweep them.

### 2.5 Per-role model selection (MEDIUM — cheap, and the obvious cost win)

`RunOptions` was deliberately built as a struct so *"per-role models later"* is a field
addition (`api-transport.md`), and `plan.md` records the same intent. Nothing has claimed it.
The shape of the win is clear on a small box: planner and critic are short, schema-constrained,
and highly cacheable; the executor is the long one. Running planner/critic on a cheap model and
the executor on a strong one is a pure-configuration change with no architectural cost.

- [ ] `RunOptions.PlannerModel` / `CriticModel` (empty ⇒ `Model`), a `models` config block, and
      `planner_model` / `critic_model` in eval variants so the trade-off is measurable before
      it is adopted.

### 2.6 No budget dial — and there is now a tool that spends real money (MEDIUM)

`plan.md` §6d's token budget has been deferred since the last review with "no active driver".
`scrape` is the driver. It is a **trusted built-in**, so it bypasses the broker, the tier, and
the approval gate entirely — the only brakes are two sentences of prompt text ("try web_fetch
first", "do not retry a scrape in a loop") and a 120-second timeout. With `max_iterations = 20`
and `permissive` on the deployed machine, a page that argues the agent into retrying is a
20-call bill, and `[browser]` calls are ~10× credits.

- [x] Document the exposure: **done 2026-08-20** — `security.md` gained §4a ("`scrape` — a
      trusted built-in that spends money"), listing what does and does not constrain it, and the
      threat→control map gained a row marking runaway spend as *unmitigated*.
- [ ] Per-run and per-day **call budgets** for paid tools (`limits.max_scrape_calls_per_run` /
      `_per_day`, counted off the audit log the way `usage.Ledger` already counts tokens).
      Exceeded ⇒ the tool returns a refusal the model can act on, not an error.
- [ ] The token budget from §6d, now that the same `Ledger` machinery serves both: soft warning
      fed into context at ~80%, optional hard stop. One dial, two meters.
- [ ] Consider routing `scrape` through the broker as a real capability rather than a trusted
      built-in, so tier and approval apply. That is the boundary the rest of the system uses for
      exactly this shape of risk, and `scrape` is the first built-in whose blast radius is
      financial rather than local.

### 2.7 Smaller flexibility items (LOW)

- [ ] `recall`'s token-overlap search is documented as producing real false negatives

      entry's `tags` and key path segments alongside the value, and let `recall` match on those.
- [ ] `turn_log_char_cap` (`cmd/deliberate.go`) remains the last unconfigurable limit; still

- [ ] `agent eval --addr` and `repeat: N` stay deferred from the last review; `repeat: N` gets
      more valuable as soon as §2.5 makes model mixes comparable.

## 3. Informativeness — letting the agent and the CLI say what is true

### 3.1 Self-docs retrieval is all-or-nothing (see §1.3 for the cost side)

`read_self_docs` offers `topic` (whole document) or `query` (list of documents). There is no way
to read *part* of a doc, and `Search` ranks whole documents by token overlap over the entire
body — so a query for "spaces" scores `usage.md` highly and returns 54k chars of which ~2k are
about spaces.

- [x] **Done 2026-08-21.** `Docs.Search` now ranks `Hit`s (one per section, heading matches
      weighted double) and renders them as `topic#slug`; `Docs.Outline` and `Docs.Section` are
      the new accessors, with the selector falling back slug → prefix → substring → 1-based
      index and a miss listing the doc's sections. The self-docs prompt note tells the agent to
      query first and cite the section it answered from.

### 3.2 `status` cannot report the agent's actual configuration (MEDIUM)

`status` reports model, tier, run id, build, counts, context fill, host, and disk. It does not
report:

- **the active space** — the agent can only infer it from the prompt note,
- **the workspace path** — where its memory and spaces actually live,
- **which prompt files loaded** (`SYSTEM.md`? whose? config-dir or workspace? tier-gated out?),
- **whether the turn is deliberate**, and with what revision budget.

Those four are precisely what a user asks when something behaves unexpectedly, and precisely
what the agent currently has to guess at. `cmd`'s `loadPrompts` already knows the answer to the
third; it just doesn't pass it on.

- [ ] Add a **Configuration** section to `status`: active space (id + name), workspace path,
      loaded prompt files (path + which layer won), agent-type catalog size and sources,
      deliberate on/off + `max_revisions`. `StatusDeps` is already the seam and `cmd` already
      resolves all of it.

### 3.3 The engine can't be asked what it is running (MEDIUM)

There is no `GET /config` (or `GET /status`). A remote user — the primary user, on Telegram —
has no way to see the serve defaults, the tier ceiling, which prompt files are live, or whether
the last `/reload` took effect. `POST /reload` returns success without saying *what* changed.

- [ ] `GET /config` returning the effective serve defaults, tier ceiling, prompt-file provenance,
      agent-type list, and limits. Read-only, no secrets (names only, as `config secrets` does).
- [ ] Have `POST /reload` return a short diff ("SYSTEM.md: unchanged; AGENTS.md: 1.2 KB → 1.4 KB;
      agents/: 3 types, +1 `worker`") and have Telegram's `/reload` echo it. Today the user
      edits a file, sends `/reload`, and gets no evidence either way.

### 3.4 Errors don't carry the recovery path (LOW, high ratio)

- [ ] Unknown space ⇒ list the available spaces (this is §1.7's other half, and it is what makes
      a mistyped `/space` self-correcting rather than a wedged session).
- [ ] Unknown model ⇒ `usage.md` already documents that a bad `/model` fails on the next turn
      with the provider's error. Echo `/model -` in that error.
- [x] `agent audit` against a dead engine ⇒ omit `--addr` to read the on-disk log (§1.5).
- [ ] `recall` already does this well ("no direct match for …; the N most recent entries…") —
      that pattern is the model to copy.

### 3.5 Doc navigation (LOW)

`usage.md` is 992 lines and growing by a section per feature; it is simultaneously the
quickstart, the command reference, the feature guide, and the ops manual — and the most
expensive thing the agent can read.

- [ ] Split it once §3.1 lands (or instead of it): `usage.md` = install + the two ways to run +
      command reference; `features.md` = spaces, memory, artifacts, self-docs, scrape, secrets;
      `operations.md` = audit, usage, sessions, Telegram, multi-agent. Each stays under ~15k
      chars, which is roughly one `read_self_docs` call's worth.
- [x] Add a **"Docs map"** section to `README.md`. **Done 2026-08-20** — — three tiers (reference / adr / planning),
      what's embedded, and which doc answers which question. The tiering is a real strength and
      is currently only explained inside `usage.md` §Self-documentation.
